reachability_gng — Quick Start

Growing-Neural-Gas reachability/capability clouds for the ceiling workcell, shown live in RViz with MoveIt MotionPlanning. One cloud per arm (arm_1 green, arm_2 orange), nodes colored by manipulability. Table_1 focus; table rotation ±180°, home −90°. Drives an energy-aware pick (arm selection + base placement, card C).

0 · Build once

cd ~/arm_WS/ceiling_arm/ros2_ws
source /opt/ros/humble/setup.bash
colcon build --packages-select reachability_gng --symlink-install
source install/setup.bash

# generate the two GNG maps -> /tmp/arm1_model.npz, /tmp/arm2_model.npz
cd ~/arm_WS/ceiling_arm
ros2_ws/src/reachability_gng/build_maps.sh

Adding arm_3/arm_4 later = one line in build_maps.sh + a config YAML.

0b · Tune the cloud (samples & node count)

build_maps.sh reads env vars (defaults N=80000 LAM=60 MAX_NODES=3000 EPOCHS=2 BOUNDARY=600 BOUNDARY_TAU=0.4 → 3000 nodes = 600 pinned boundary shell + ~2400 interior). Interior count ≈ N × EPOCHS / LAM; the shell is independent of LAM.

N=200000 ros2_ws/src/reachability_gng/build_maps.sh   # more FK samples (denser, slower)
LAM=160  ros2_ws/src/reachability_gng/build_maps.sh   # ~1600 nodes (600 shell + ~1000 interior)
BOUNDARY=1000 ros2_ws/src/reachability_gng/build_maps.sh  # denser edge shell
BOUNDARY=0    ros2_ws/src/reachability_gng/build_maps.sh  # legacy centroid-only map

Boundary seeding (why the edge is now honest): plain GNG nodes settle at Voronoi centroids, so the hull sits ~0.26 m inside the true reachable surface — a genuinely-reachable object near the edge then scored 0% reach. BOUNDARY>0 detects the outer FK samples (kNN one-sidedness, no voxels) and pins them as a fixed shell that adaptation never moves and pruning never deletes, so the hull reaches the true surface exactly (0.00 m short). Raise BOUNDARY_TAU if the shell balloons to stray samples.

Fewer nodes, same coverage — now safe: because the shell is pinned, raising LAM only thins the interior; the outer extent and edge fidelity hold. Pick LAM ≈ N×EPOCHS / (target interior) → 110≈1450, 160≈1000, 320≈500. Keep N high (samples define what the shell can cover).

Then reload: pkill -9 -f lib/reachability_gng/visualize and relaunch gng_clouds.launch.py / launch_workcell.sh.

A · With Isaac Sim recommended

Robot driven by the Isaac digital twin; plan in RViz, watch it move in Isaac (noVNC: http://<server>:22380/vnc.html).

cd ~/arm_WS/ceiling_arm
./isaac_sim/stop.sh            # clear any old session

C · Perception → energy-aware pick

Detected objects → choose which arm (arm_1/arm_2, shared gantry_1) and the 8-DOF goal by energy, then MoveIt plans collision-aware. Needs A (move_group + cameras) up.

# cameras + scene collision (objects, env octomap)
ros2 launch reachability_gng perception.launch.py

# the executor — plan-only (robot stays put)
ros2 launch reachability_gng gantry_pick.launch.py csv:=/tmp/picks.csv
ros2 topic pub --once /gantry_reach_executor/pick std_msgs/String "{data: '0'}"
column -t -s, /tmp/picks.csv

# or drive picks from an interactive menu (second terminal)
ros2 run reachability_gng pick_cli

# execute for real (arm moves in Isaac)
ros2 launch reachability_gng gantry_pick.launch.py execute:=true csv:=/tmp/picks.csv

pick_cli lists the live /detected_objects (with labels + a cheap object→arm-tool distance estimate, not energy J) and fires a pick by index — a friendlier stand-in for the ros2 topic pub .../pick one-liner. Watch the executor terminal for the chosen arm / plan result.

Each candidate scored J = w_gantry_lin·d_gantry_lin + w_gantry_rot·d_gantry_rot + w_arm·d_arm + w_dist·ee_dist − w_manip·manip (gantry linear/prismatic and rotation axes weighted separately; ee_dist = the arm's CURRENT tool-frame Euclidean distance (via TF) to the object, one value per arm, so it biases allocation toward the nearer end-effector — w_dist=0 to disable; the gravity hold cost was removed from J but is still logged to the CSV). A farther seed with lower J can still win. Calibrated default weights lin 1 / rot 1 / arm 2 / dist 1 / manip 0; override live with -p w_manip:=300 etc.

Needs the maps' _stats.npz to carry hold (train with --config, or augment an existing map). Grasp orientation defaults top-down (1,0,0,0) — the centroid's identity quat is unreachable (IK err −31).
